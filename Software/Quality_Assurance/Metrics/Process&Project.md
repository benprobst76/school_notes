* Process metrics: measurements related to the software development and maintenance process itself.
* Project metrics: quantifiable measures to monitor the project.
### Process Metrics
A quantitative measure to gain insight into the effectiveness and efficiency of the software development and maintenance process itself:
* Understand the current state, performance, and maturity of the software process.
* Forecast resource needs (effort, cost, schedule), and the likely quality of the final product.
* Pinpoint bottlenecks, weaknesses, and inefficiencies in the workflow.
* Continuous process improvement.

| Metric          | Main Focus                                                                            | Example metric                                                                                                      |
| --------------- | ------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| Process Metrics | Effectiveness and efficiency of the development activities and workflow               | Cycle Time, Defect Removal Efficiency (DRE), Code Review Effectiveness                                              |
| Product Metrics | Characteristics of the software itself (e.g., size, complexity, quality, reliability) | Lines of Code (LOC), Cyclomatic Complexity, Defect Density, Mean Time to Failure (MTTF), Mean time to repair (MTTR) |
| Project Metrics | Project management attributes (e.g., cost, effort, schedule, productivity)            | Schedule Variance, Effort Variance, Team Velocity, Staffing Pattern                                                 |
### Example Process Metrics
* Cycle time: total time taken to complete a task, feature, or user story from start to finish.
* Defect Removal Efficiency (DRE): To compare defects found before release to those found after release.
* Defect Injection Rate: The rate at which defects are introduced into the software during a specific phase.

### Process Metrics in Agile 
Metrics related to speed and flow (Kanban focus):
* Cycle Time: time taken for a work item (a user story or bug fix) to complete and ready for delivery from the beginning.
* Lead Time: time taken when a work item is added to the backlog (request made) until it's delivered.
* Throughput: number of work items (stories, tasks, etc.) completed over a fixed period.
* Work In Progress (WIP) Limit: a process rule that restricts the number of tasks being worked on at any given time (not a metric itself).

Metrics related to Predictability and Capacity (Scrum focus):
* Velocity: The sum of the estimation units (usually story points) for all the features or stories successfully completed in a single Sprint.
* Sprint Burndown: A visual chart that tracks the amount of work remaining in a Sprint against the time left.
* Defect Escape Rate: The ratio of defects found by the customer after release compared to the total number of defects found.

### Project Metrics
A quantitative measure used to assess the progress, quality, cost, and efficiency of a software project. Often used for estimation and control.
####  Examples 
- Schedule Variance (SV): Difference between the planned completion date and the actual progress. 
- Cost Performance Index (CPI): Measures the cost efficiency of the project=> value greater than 1.0 is favourable.
- Cycle Time: The time elapsed from when work begins on a task until it's complete and delivered.  
- Effort/Size Estimation Accuracy: The difference between the estimated effort (or size) and the actual effort (or size).
