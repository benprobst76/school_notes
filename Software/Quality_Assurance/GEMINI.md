## Directory Overview

This directory serves as a collection of notes and documentation related to software engineering topics, primarily focusing on software testing and metrics. It also contains a summary of a specific software project.

## Key Subdirectories and Files

*   **`A4_Probst_4512.md`**: This file likely contains assignment or project-specific documentation.
*   **`GEMINI.md`**: This file serves as the overview and guide for the entire directory.
*   **`Library Managment System.md`**: This file provides a summary and reflection on a specific "Library Management System" project, including links to a GitHub repository, implementation details, AI-assisted test generation, and the project's CI/CD pipeline.

*   **`media/`**: This subdirectory contains images and other media files used throughout the notes.

*   **`Metrics/`**: This subdirectory contains detailed notes on software metrics.
    *   **`Code&Structure.md`**: Discusses code size and complexity metrics, focusing on Function Point Analysis (FPA) and Story Points as alternatives to LOC.
    *   **`Cost-Estimation.md`**: Covers cost estimation models, with a deep dive into the COCOMO (Constructive Cost Model).
    *   **`Measurement.md`**: Lays out the fundamentals of software measurement, including the definition of measurement, direct vs. indirect measures, and their use in assessment and prediction.
    *   **`Process&Project.md`**: Differentiates between process, project, and product metrics, and provides examples of metrics used in traditional and Agile (Scrum, Kanban) development.
    *   **`Product.md`**: Details metrics for the software product itself, covering external attributes like reliability (POFOD, ROCOF) and internal attributes like size (LOC) and complexity (Halstead's Software Science, McCabe's Cyclomatic Complexity).
    *   **`Software-Metrics.md`**: An introductory overview of software metrics, their purpose, and the three basic kinds (product, process, project).

*   **`Quality_Assurance/`**: This subdirectory contains a comprehensive set of notes on software quality assurance principles and practices.
    *   **`Industry-Practice.md`**: Details industry-standard V&V (Verification and Validation) practices, including the role of CI/CD, project management tools (Jira), coding standards (PEP 8, MISRA C), linters (ESLint), and various testing tools (Jest, Selenium, Cypress).
    *   **`Inspection.md`**: Provides a thorough guide to formal software inspections, including Fagan inspections, roles (Moderator, Author), the step-by-step process, and techniques like code paraphrasing.
    *   **`Security.md`**: Covers key software security concepts within SQA, including the CIA Triad, threat modeling (STRIDE, Attack Trees), SAST vs. DAST, and common vulnerability lists like the OWASP Top 10.
    *   **`SQL-Injection.md`**: A focused document explaining SQL Injection attacks, with examples of malicious inputs and a detailed breakdown of prevention techniques like parameterized queries, input sanitization, and the principle of least privilege.
    *   **`media/`**: Contains images and media for Quality Assurance notes.

*   **`Testing/`**: This subdirectory contains a comprehensive set of notes on software testing.
    *   **`Black-Box-Testing.md`**: Notes on black-box testing methodologies.
    *   **`Continuous-Testing.md`**: Notes on continuous testing and its practices.
    *   **`Levels-of-Testing.md`**: Notes covering different levels of testing (unit, integration, system, acceptance).
    *   **`Testing-Examples.md`**: Provides examples related to software testing.
    *   **`Testing.md`**: General principles and overview of software testing.
    *   **`White-Box-Testing.md`**: Notes on white-box testing methodologies.
    *   **`media/`**: Contains images and media files related to testing notes.

## Usage

This directory is intended for educational purposes, for studying and reviewing concepts in software engineering. The `Testing` and `Metrics` directories provide organized notes on their respective topics, while the `Library Managment System.md` serves as a case study or project report.  When asked to reformat notes, rewrite them so that they are in proper markdown format and are optimized to be used in obsidian. Do not include a newline  after paragraphs, headers or sections. Also when asked to reformat include extra details or examples for concepts if it helps makes the notes clearer and easier to understand.
